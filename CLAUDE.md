## Project Overview

TORCCVODE is a C++ combustion simulation code that models transient two-phase reactive flow for droplet combustion. It solves coupled gas-phase and liquid-phase transport, chemical kinetics, and droplet/gas interface interactions in 1D (planar, cylindrical, or spherical geometry). The current focus (branch `lag_solver`) is on implementing an improved iterative solver for the droplet-gas interface.

## Build Commands

```bash
# Configure (from project root)
cmake -B build -DCMAKE_BUILD_TYPE=Release

# Build
cmake --build build

# Run (must run from project root, where input.dat and data files are)
./build/TORCCVODE
```

The executable name is `TORCCVODE`. There are no tests or linter configurations.

## Architecture

### Computational Flow

1. **Initialization** (`main.cpp`): Parse `input.dat`, allocate `UserData`, read initial conditions from binary `.dat` files, set up CVODE (BDF + Newton) and KINSOL solvers.
2. **Time integration loop** (`main.cpp`): CVODE advances the solution one step at a time. Each step calls the RHS function, updates the interface state, tracks droplet mass/radius, and periodically writes output.
3. **Termination**: Simulation ends when droplet radius drops below 10% of its initial value or `finalTime` is reached.

### Key Source Files

- **`src/residue.cpp`** (~4700 lines): The core of the code. Contains `funNew()` (the RHS/residual function called by CVODE at every timestep), interface transport calculations (`getInterfaceTransport`, `getInterfaceMassFlux`), interface state update (`updateInterfaceCell`), and diagnostic utilities (`maxTemperature`, `isothermPosition`).
- **`src/UserData.cpp`** (~1170 lines): `allocateUserData()` reads `input.dat`, initializes Cantera gas/transport objects (thread-local for OpenMP), allocates all arrays. `freeUserData()` handles cleanup.
- **`src/main.cpp`** (~470 lines): Entry point, solver setup, main time-stepping loop, output writing.
- **`src/gridRoutines.cpp`**: Adaptive grid management for focusing resolution near the flame zone.
- **`src/solution.cpp`**: Solution vector allocation helpers.

### Key Header Files

- **`include/UserData.h`**: Defines the central `UserData` struct (~50+ fields) holding all simulation state: grid parameters, species info, droplet properties, solver tolerances, Cantera object pointers, output file handles. Also defines `LiquidFuelProperties` (CoolProp wrapper).
- **`include/macros.h`**: Preprocessor macros for indexing into the solution vector. `T(i)`, `Y(i,k)`, `P(i)` access temperature, species mass fraction, and pressure at grid point `i`. `Tdot(i)`, `Ydot(i,k)`, `Pdot(i)` access their time derivatives. Grid indexing is 1-based via these macros. The solution vector is interleaved: each grid point stores `nvar` values (temperature, `nsp` species, pressure).
- **`include/residue.h`**: Declarations for all residual/RHS functions.
- **`include/newForSolver.h`**: Isobaric reactor wrapper for Cantera integration.

### Solution Vector Layout

The solution vector `y` is a flat array indexed as: `y[(i-1)*nvar + offset]` where `i` is the 1-based grid point index. Each grid point stores `nvar` variables: temperature (`nt` offset), species mass fractions (`ny` offset + species index), and pressure (`np` offset). The macros in `macros.h` abstract this.

### Thread Safety

Cantera `gas` and `trmix` objects are declared `thread_local` in `UserData.cpp` so each OpenMP thread gets its own chemistry instance. The number of threads is controlled by `nThreads` in `input.dat` (0 = use all available).

## Input Files

- **`input.dat`**: Plain-text key=value configuration (grid size, tolerances, chemistry file, initial conditions, etc.)
- **`initialCondition.dat`** / **`initialLiquidCondition.dat`**: Binary files with initial gas/liquid state, generated by `initDropTwoPhaseFuelInGas.py`
- **`NH3_NC7.xml`** / **`NH3_NC7.cti`**: Cantera chemistry mechanism (ammonia + n-heptane)
